## Multi-track rules

- **SERV: yes, several tracks.** The live submission form asks "Which track are you selecting for the
  hackathon? (Select all that apply)", `allow_multiple_selection: true`, with four options: Robinhood
  Chain / MCP, Coinbase AgentKit, IXS Vaults, Open Track [2]. Nothing on the page forbids it [1].
  Not stated: whether one project can win two tracks. "Four tracks, four winners" [1] suggests one
  prize per project.
- **Arbitrum: not stated.** The pages list Overall and Promising Products with the same criteria and do
  not say whether a project can be in both [7][8]. HackQuest's own submit flow decides. Ask in the
  Buildathon channel.
- **Across events: allowed.** Neither event forbids submitting the same project elsewhere. Arbitrum
  says "Bring an existing project" [7]. SERV wants it "new, working, and demoable by 28 September"
  [1], which Shijima is.

## SERV submission details (from the live form [2])

- Email must be "the email address you used to register on console.openserv.ai" (required).
- "Did you enable data collection?" is required. It says to turn "Collection is on" in the
  Organization tab **and "perform at least one full run of your agent"**, so they can check SERV use.
- Required: the public X post link tagging @openservai, project name, description, demo or GitHub link.
  Also asks for a logo for their promotion.
- SERV does not require the OpenServ SDK or platform. It requires only "leverages SERV Reasoning" [1].
  Shijima uses both anyway (`apps/worker/package.json`: `@openserv-labs/sdk` 2.4.1, `@openserv-labs/client` 2.5.3).

## Coinbase

- **SERV:** one track is about Coinbase AgentKit [1]. Coinbase is not named as a partner. Only IXS
  has a "TRACK PARTNER" label. The prize is $1,000 in SERV like the other tracks.
- **Arbitrum:** no Coinbase, CDP, AgentKit, x402 or Base bounty. Zero mentions on the blog, the site
  or the HackQuest page (checked with grep in `.firecrawl/tracks/`) [7][8][9].
- **AgentKit on Robinhood Chain is possible.** AgentKit's `ViemWalletProvider` "is useful for
  interacting with any EVM-compatible chain", and a custom `ActionProvider` can set
  `supportsNetwork = () => true` [10]. Our operator signer is already a viem `WalletClient` on the
  Robinhood chain (`apps/worker/src/cli/context.ts:34-35`). Not verified: whether AgentKit's built-in
  action providers accept chain 4663. A custom action provider does not need them.
- Known AgentKit competitor: AllowLatch, on Base (`docs/research/2026-09-19-project-links.md:29`).

## Recommendation

1. **SERV: tick Mainnet & MCP and Open Track.** Both fit today at no cost. Submit on form
   **A475N331**, not GyPxGqRn.
2. **SERV: add AgentKit if half a day is spare.** Wrap the existing operator `WalletClient` in
   AgentKit's `ViemWalletProvider`. Expose the desk's actions (rebalance, pause, switch strategy) as an
   AgentKit `ActionProvider`. Then every trade the SERV agent makes is an AgentKit action on Robinhood
   Chain, and we can tick a third track. Risk: judges may expect Base or a CDP wallet. The track text
   names no chain.
3. **SERV: skip RWA Vaults.** It needs IXS vaults on BNB Chain or Base Sepolia, in USDC or USDT, not
   USDG [4][6]. That means a second chain and a bridge. IXS builds its deposit transactions through
   its own MCP server [6], which conflicts with our no-MCP decision. It costs a lot for one $1,000 track.
4. **Arbitrum: enter Overall and Promising Products.** Register on HackQuest before **2 Oct**. Submit
   before **4 Oct** (plan for 3 Oct, since the time zone is not shown). Their criteria favour things we
   have: our own contracts, USDG, and Robinhood Chain, with a reserved place in each prize list. Of all
   the options this has the most money at stake: $70K + $15K, against $1K-$2K at SERV.
5. **Fix in our docs:** the Typeform swap, the "best overall" rule, and the MCP track question now
   answered (`BUILD-PLAN.md` Risks, `DECISIONS.md:299`, `ABU-CHECKLIST.md:20-22`).
